# Result summaries

These are the summary files behind the tables in the paper. They are the direct
output of the `val/` scripts, so the reported numbers can be checked without
re-running anything.

| File | Paper | Notes |
| --- | --- | --- |
| `batch_baseline.summary.json` | Table 3, *Direct* column | single forward pass, no refinement |
| `batch_eval.summary.json` | Table 3, *Refined* column | after per-image refinement |
| `retrieval_baseline.summary.json` | Table 4, *Direct* column | CBIR retrieval, network-output queries |
| `retrieval_eval.summary.json` | Table 4, *Refined* column | CBIR retrieval, refined queries |
| `external_trustmark.summary.json` | Table 5 | cross-system comparison against TrustMark |
| `transfer_eval.summary.json` | Table 6 | retrieval in uncalibrated backbones |
| `channel_retrieval.summary.json` | Section 5.9 | retrieval after the transmission channel |

Settings common to all of them: 1,000-image test set, 100 queries over a
1,000-image gallery, seed 42, `prv_budget = 0.08`, `margin = 0.50`, 30 refinement
steps, and the checkpoint attached to the
[latest release](../../releases/latest).

Each file was produced by the script of the same name:

| Summary | Regenerate with |
| --- | --- |
| `batch_baseline.summary.json` | `python val/batch_baseline.py -c <checkpoint> --num-images 1000 -o out` |
| `batch_eval.summary.json` | `python val/batch_eval.py -c <checkpoint> --num-images 1000 -o out` |
| `retrieval_baseline.summary.json` | `python val/retrieval_baseline.py -c <checkpoint> --num-queries 100 --gallery-size 1000 -o out` |
| `retrieval_eval.summary.json` | `python val/retrieval_eval.py -c <checkpoint> --num-queries 100 --gallery-size 1000 -o out` |
| `external_trustmark.summary.json` | `python val/run_full_validation.py --stages external --val-dir <test dir> -o out` |
| `transfer_eval.summary.json` | `python val/transfer_eval.py --num-queries 100 -o out` |
| `channel_retrieval.summary.json` | `python val/channel_retrieval_eval.py -o out` |

Per-image records (`results.json`), gallery feature caches (`gallery_feats.pt`)
and the visual reports are not included: they are large and are regenerated by
the same commands.
